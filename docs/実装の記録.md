# 実装の記録

「今日の先行研究」を作ってきた経緯と、設計の理由のまとめです（2026年11月時点）。

## 1. 前提：ゼミのメンバーへの配布を見据えている

- 持ち主が自分用に作り始めたが、ゼミのメンバーがそれぞれ自分用の推薦を受けられるよう、配布することまで考えて作っている。
- 1つのページを共有する形は採らない。反応や既読論文は人ごとのデータで、毎朝の推薦はページの持ち主のアカウントの定期タスクで動くため。各自が自分の環境で立ち上げる「キット」方式にした。
- Claudeを使わないメンバーのために、Gemini版も用意した。

## 2. Claude版の構成

- 画面：Claudeの artifact（HTMLページ1枚）。タブは「推薦」「変数の集計」「関心テーマ・既読論文」「PDFの入手手順・AIの動作について」。タブの切り替えはURLのハッシュで行う（#feed、#variables、#prefs、#howto）。#settings は claude.ai の予約語なので使わない。
- データ：artifact の db 機能（Firestore に近い形）。ページからは `claude.use("db")` で読み書きする。
- 宣言する機能：db（rules：papers と config は write admin）、user、sample（PDFの読み取りに使う）。
- 毎朝の推薦：Claudeの定期タスク。新しいセッションで動き、自動承認にする。

### データの形

- papers/{YYYYMMDD}-{枠番号}：推薦した論文。title, authors, journal, journalName, volume, issue, pages, year, doi, url, jstorUrl, oaUrl, issn, conclusion, diagram, conclusionSource, method, tags, peer, basis, connection, role, slot, date
- reactions/{論文ID}：status は read（読んだ・興味あり）／later（あとで読む）／pass（パス）
- reads/{id}：ページで登録した既読論文。PDFから登録したものは refs（引用文献の一覧）を持つ
- varRequests/{id}：探してほしい変数（open／done）
- config/settings：interests（関心テーマ）、readPapers（まとめて登録した既読論文）
- config/auto、config/proposals、config/insights：週1回の見直しで定期タスクが書く

### 毎朝の推薦の流れ（定期タスク）

1. 初期設定（関心テーマ）がなければ何もしない。今日の分がすでにあれば二重に書かない。
2. 既読論文、反応、探してほしい変数を全件読む（db_list は1回100件までなので最後まで読む）。
3. 役割ごとに選ぶ。
   - 縦の深掘り：既読論文（PDFから登録したものは、その引用文献リストを最優先）の引用文献から選ぶ。
   - 横の広がり：探してほしい変数を優先し、なければ関心テーマの周辺。
   - 遠い分野：関心テーマから少し離れた概念や手法。
4. 書誌を確かめる。日本語はJ-STAGEの記事ページ、英語はCrossrefとOpenAlexで、DOIの実在と書誌の一致を確かめる。
5. 要旨を取る（J-STAGEの抄録、OpenAlex の abstract_inverted_index、Crossref の abstract）。取れなければ載せない。
6. 結論とパス図を書き、矢印を1本ずつ要旨の文と照合する。根拠のない矢印は消す。変数の意味（数か、程度か）が要旨と合っているかも確かめる。
7. 査読の判定：論文ページに「受付」「受理」の日付があれば査読あり。
8. 月曜は見直し：今週の傾向、自動テーマの追加と削除、関心テーマの提案。

## 3. 途中で起きた問題と直し方

- 論文のDOIが誤っていた（二次情報から取った）→ Crossrefで実在を確かめる手順を追加。
- 結論をブログの記述から書いていた → 要旨や本文だけを根拠にするルールを追加。
- 結論が要旨と食い違っていた（孤立した人の「数」と孤立の「程度」の取り違え）→ 変数の意味を照合する手順を追加。
- 反応の序列が分かりにくかった → 「読んだ・興味あり／あとで読む／パス」の3択に変更。
- 配布用zipのファイル名が文字化けした → 日本語ファイル名にUTF-8の目印を付け、.md の先頭にBOMを付ける（`scripts/build_zips.py`）。

## 4. 補助ツール（tools/）

- ページは外部サイトからPDFを取れず、パソコンのフォルダにも書けない。そのため、PDFの保存は「ページで保存依頼ファイルを作る → パソコン側の .bat がPDFを取って保存する」の2段階にしている（持ち主のページのみ。キット版のページにはまだ入れていない）。
- J-STAGEのPDFは編集制限の鍵がかかっていて、Windowsの標準機能だけでは中の文字を読めない。PDFの改名ツールは Python と pypdf・cryptography を使う。
- 改名ツールのタイトルの取り方は「DOI → 1・2ページ目で一番大きな文字 → PDFに埋め込まれたタイトル（本文に同じ文字列があるときだけ）」の順。埋め込みタイトルにはデータベース名や雑誌の巻号が入っていることがあるため、最後に回している。

## 5. 残っていること

- キット版ページ（PDFからの既読登録を含む）とGemini版は、まだ実際に立ち上げて試していない。
- `論文を保存.bat` は、まだWindowsで動かしていない。
